Fine-tuning changes model weights. RAG adds external knowledge at query time. They complement each other in production systems.

Step-by-Step Learning Flow

1

Understand the Dataset

Open Dataset tab. Each row in sample_dataset.jsonl:

{
  "instruction": "What is LoRA?",
  "input": "",
  "output": "LoRA is a parameter-efficient fine-tuning method..."
}

15 examples about AI concepts. Model learns: given instruction → produce output.

2

Train LoRA Adapter

  1. Open Train tab
  2. Set epochs (start with 3)
  3. Click Start LoRA Training (main app) or Start Training (standalone)
  4. Wait 5–15 minutes on CPU
  5. Output: fine_tuning/outputs/lora_adapter/

Only a small fraction of parameters (approximately 1%) are trained as LoRA adapters.

3

Run Inference

  1. Open Infer tab
  2. Enter: What is LoRA?
  3. Check: Adapter used: Yes
  4. CLI: python fine_tuning/scripts/infer.py "What is RAG?"
4

Evaluate

  1. Open Evaluate tab
  2. Click Compare Base vs Fine-Tuned (main app) or Run Evaluation (standalone)
  3. Side-by-side: base model vs adapter model
  4. CLI: python fine_tuning/scripts/evaluate.py
5

Export (Optional)

python fine_tuning/scripts/export.py

Merges adapter into full model at fine_tuning/outputs/merged_model/

Key Concepts

ConceptExplanation
Full fine-tuningUpdate ALL weights — expensive, needs GPU
LoRATrain small adapter matrices — cheap, CPU-friendly
Instruction tuningTeach model to follow instruction → output format
AdapterSmall file saved after training, loads on top of base
Eval lossLower = better fit (watch for overfitting)

Exercises

  • Train with 1 epoch vs 5 epochs — compare eval loss
  • Add your own row to sample_dataset.jsonl — retrain
  • Read trainer.py — find LoraConfig settings
  • Run export.py — understand merged vs adapter weights
  • Compare: same question to Chat tab (prompt) vs Fine-tuned infer (weights)
